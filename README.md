# AntiLag 流畅优化（SillyTavern 扩展）

一个只做「渲染层减负」的 SillyTavern 扩展：不碰角色卡、世界书、聊天记录，也不改任何其他扩展的数据，靠 CSS 渲染优化 + 运行时体检 + 自动降级来压低卡顿。

适配：桌面端 / 移动端（手机 APP、浏览器都可用），长聊天、重特效主题、流式输出场景收益最明显。

仓库：<https://github.com/Neohero521/SillyTavern-AntiLag>

---

## 卡顿到底卡在哪

SillyTavern 的卡顿绝大多数不是「模型慢」，而是浏览器在重复做昂贵的绘制：

| 现象 | 真正原因 | 本扩展的解法 |
| --- | --- | --- |
| 聊天一长、滚动就一顿一顿 | 几百条消息全部参与布局和绘制 | 消息虚拟化（`content-visibility`），视口外的消息直接跳过布局与绘制 |
| 主题很好看但整体发黏 | `backdrop-filter` 毛玻璃、大面积 `filter: blur()`，每帧都要重新采样背景 | 关闭毛玻璃/滤镜（可一键开关） |
| 流式输出时越打越卡 | 每个 token 都重绘最后一条消息 + 阴影/滤镜/过渡叠加 | 生成中轻量渲染：只对最后一条消息去掉重特效 |
| 滚动时图片解码掉帧 | 所有图片同步解码 | 图片 `loading="lazy"` + `decoding="async"` |
| 背景在动、CPU 一直高 | 动画背景 / `background-attachment: fixed` | 停用动画背景与固定背景 |
| 输入时偶尔整屏僵住 0.3s+ | 主线程长任务（大聊天渲染、重扩展定时器） | 长任务监控 + 体检定位 |

## 功能

**面板位置**：`扩展` 抽屉 → 最下方 `AntiLag 流畅优化` 卡片。

- **基础**：总开关、生成时轻量渲染、悬浮仪表、状态提示
- **渲染减负**：消息虚拟化、关闭毛玻璃/滤镜、关闭阴影、停用动画背景、图片懒加载
- **历史管理**：折叠较早消息（默认关），可设保留条数；折叠后聊天顶部出现「展开」按钮，随时还原
- **体检与自动降级**：实时帧率、长任务次数与最长耗时、DOM 节点数、毛玻璃元素数、动画背景检测、已启用扩展数
- **一键优化**：把推荐组合一次性打开（虚拟化 + 关毛玻璃 + 生成轻量 + 懒加载 + 停动画背景 + 自动降级）
- **悬浮仪表**：右下角小球，显示实时 FPS，可拖动、轻点展开详情；颜色会随帧率变化（绿/黄/红）

**自动降级**：连续 3 秒帧率低于阈值，自动临时进入「极速模式」（不写入你的设置，帧率恢复 12 秒后自动退出），避免手动来回切。

## 安装

### 方式一：手动放入（最稳）

1. 把整个 `antilag` 文件夹放到：
   - 桌面版：`SillyTavern/public/scripts/extensions/third-party/antilag`
   - 新版数据目录安装：`SillyTavern/data/<你的用户名>/extensions/antilag`
2. 重启 SillyTavern（或刷新页面）。
3. 打开「扩展」抽屉，确认出现 `AntiLag 流畅优化` 卡片并处于启用状态。

### 方式二：从本地 zip 安装

1. 解压 `antilag.zip`；
2. 按方式一把解压出的 `antilag` 目录放到位；
3. 刷新页面。

### 方式三：扩展管理器 URL 安装

在「扩展 → 安装扩展」里填仓库地址：

```
https://github.com/Neohero521/SillyTavern-AntiLag
```

（仓库根目录已带 `manifest.json`，可直接识别。）

## 建议怎么用

1. **先点「重新检测」**，看体检结论里的红黄项，哪项红就先开对应的开关。
2. **长聊天（>300 条）**：开「消息虚拟化」，这是收益最大的一项。
3. **用了毛玻璃/发光/模糊主题**：开「关闭毛玻璃 / 滤镜」。画面会变朴素，但掉帧通常直接减半。
4. **手机端**：建议再开「折叠较早消息」，保留 80–150 条，滚动会明显跟手。
5. **想保留主题观感**：只开「生成时轻量渲染 + 图片懒加载 + 消息虚拟化」，视觉几乎无损。
6. 自动降级保持开启，它是兜底：真掉帧了会自己顶一下。

## 体检指标怎么看

| 指标 | 含义 | 判断 |
| --- | --- | --- |
| 帧率 | rAF 实测帧率 | 低于阈值（默认 28）就是真卡；45 以下算偏黏 |
| 消息条数 | 当前聊天消息数量 | 300 以上必须开虚拟化 |
| DOM 节点 | 页面元素总数 | 4000 以上说明渲染树偏重（多为长聊天 + 多扩展 UI） |
| 10s 长任务 | 最近 10 秒主线程阻塞次数 / 最长一次 | 单次 >150ms 会有可感知的「顿一下」 |
| 毛玻璃元素 | 抽样 40 条消息中含 `backdrop-filter` / `filter` 的数量 | 大于 0 就值得关掉 |
| 动画背景 | 背景是否在动或 fixed | 是则滚动必掉帧 |
| 已启用扩展 | `extension_settings` 中的模块数 | 超过 10 个建议逐个排查（尤其自带 `setInterval` 的） |

## 技术实现

- 只用 `SillyTavern.getContext()` 稳定 API（`eventSource` / `eventTypes` / `extensionSettings` / `saveSettingsDebounced`），不 import 内部模块，降低升级炸掉的风险。
- 所有样式注入都挂在 `html.antilag` / `body.antilag` 根类上，关掉总开关即整段移除，不留痕。
- 帧率用 `requestAnimationFrame` 分秒采样，长任务用 `PerformanceObserver({entryTypes:['longtask']})`；两者不可用时静默降级，不影响使用。
- 生成中的轻量渲染由 `GENERATION_STARTED` / `GENERATION_ENDED` / `GENERATION_STOPPED` 三个事件驱动，只作用于 `.last_mes`。
- 聊天区用 `MutationObserver` 监听新增消息，扫描做 380ms 防抖，避免自己变成卡顿源。
- 设置存在 `extension_settings['antilag']`，随 SillyTavern 正常设置一起保存。

## 边界与副作用

- **不改内容**：不动消息文本、不重写正则、不影响世界书扫描与出戏质量。
- **虚拟化的代价**：视口外消息不参与布局，极少数情况下「跳转到很早的消息」滚动定位会有轻微偏差；在意可关掉该项。
- **关闭毛玻璃**：视觉会明显变朴素（这是它的原理，不是 bug）。
- **折叠较早消息**：只是不渲染，不删除，点「展开」全部回来；切换聊天后恢复为折叠状态。
- **不支持的浏览器**（无 `longtask`）：体检里长任务一项恒为 0，其余功能正常。
