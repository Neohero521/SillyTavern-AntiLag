# AntiLag 流畅优化（SillyTavern 扩展）

一个只做「渲染层减负 + 卡顿归因」的 SillyTavern 扩展：不碰角色卡、世界书、聊天记录，也不改其他扩展的数据。靠 CSS 渲染优化 + 运行时体检 + 自动降级压低卡顿，并且**默认档位视觉零改动**。

适配：桌面端 / 移动端（手机 APP、浏览器都可用），长聊天、重特效主题、流式输出场景收益最明显。

仓库：<https://github.com/Neohero521/SillyTavern-AntiLag>

---

## 设计原则：先不打扰，再谈优化

卡顿优化最容易犯的错，是「为了流畅把体验改坏」。所以这个扩展的默认行为是：

1. **默认「轻度」档视觉零改动**：只做不可见的减负（虚拟化 / 懒加载 / 生成隔离 / 清理 will-change）。
2. **结构性操作默认关闭**：折叠历史、裁剪超长消息都要你手动开，且随时可还原。
3. **正在编辑 / 正在选中文本时，一切结构性操作让路**：不折叠、不裁剪、不硬切样式。
4. **每次切样式先记 `#chat` 滚动位置再回填**；贴底时保持贴底，避免「优化一下跳一段」。
5. **自动降级只动视觉开销**，绝不自动隐藏内容。
6. **怀疑是它的问题**：面板里有「暂停 10 分钟」，一键还原做 A/B 对比。

## 卡顿到底卡在哪（场景对照表）

| 你会遇到的卡顿 | 真正的开销 | AntiLag 的处理 | 默认 |
| --- | --- | --- | --- |
| 聊天一长，滚动一顿一顿 | 几百条消息全量参与布局/绘制 | 消息虚拟化（`content-visibility`），仅在 ≥120 条时启用 | 开 |
| 主题好看但整体发黏 | `backdrop-filter` 毛玻璃、大面积 `filter: blur()`，每帧重新采样背景 | 关聊天区毛玻璃/滤镜（可扩到全界面、含伪元素） | 均衡档起 |
| 背景在动、CPU 常年高 | 动画背景 / `background-attachment: fixed` | 停用背景动画 + 固定背景 | 均衡档起 |
| 消息气泡发光、阴影多 | `box-shadow` / `text-shadow` 叠加 | 关消息区阴影 | 极速档 |
| 手机发烫、掉帧、切后台回来卡 | 主题滥用 `will-change`，GPU 图层堆积 | 清理 `#chat` 内被滥用的 `will-change` | 开 |
| 消息进出场动画拖慢滚动 | 每条消息的 `transition` / 关键帧 | 关消息区过渡与动画 | 极速档 |
| 流式输出越打越卡 | 每个 token 重绘最后一条消息 + 阴影/滤镜叠加 | 生成中隔离 `.last_mes`，去掉其重特效 | 开 |
| 滚动时图片解码掉帧 | 所有图片同步解码 | `loading="lazy"` + `decoding="async"` | 开 |
| 消息里嵌网页/视频卡整页 | iframe 立即加载 | iframe `loading="lazy"` | 均衡档起 |
| 单条超长回复（几千上万字）拖动卡 | 巨型文本节点反复重排 | 超长消息先折前段，点「展开全文」看全 | 关（可选） |
| 聊天几千条，找最近消息也卡 | 渲染树过大、内存占用高 | 折叠较早消息（保留最近 N 条），顶部一键展开 | 极速档 |
| 输入长文本时输入框发涩 | 输入框自动增高 + 拼写检查 + 聊天区重排牵连 | `contain: layout` 隔离聊天区（极速档）；关掉自动增高类扩展更有效 | 极速档 |
| 手机弹出键盘后整页重排、卡一下 | 键盘导致 viewport 变化，抽屉动画 + 背景 blur 叠加 | 毛玻璃/动画背景关闭后重排成本显著下降；输入区也在关闭范围内 | 均衡档起 |
| 整屏僵住 0.3s+ | 主线程长任务：大聊天渲染、世界书多条目扫描、向量检索/摘要扩展、正则脚本、扩展定时器、tokenizer 计数、频繁 `saveSettingsDebounced` | **CSS 解决不了计算**：体检里做归因（10s 长任务、生成期长任务、扩展数），提示你减条目/关扩展 | 只诊断 |
| 切换聊天/打开抽屉卡一下 | 抽屉动画 + 大面积 blur + 聊天区重排 | 关毛玻璃后明显变轻；`contain` 隔离聊天区 | 均衡档起 |
| 用久了越来越卡（内存） | 长聊天 + 大图常驻、扩展定时器泄漏 | 折叠历史释放渲染树；体检可看 DOM 节点与图片数 | 极速档 |

> 诚实边界：世界书扫描、向量检索、正则、tokenizer 这些是**主线程计算**，纯 CSS 扩展无法消除，只能帮你把「谁在拖」看清楚。真要治，得减世界书条目 / 换更轻的检索扩展 / 关掉带 `setInterval` 的扩展。

## 三档模式

| 档位 | 适合 | 包含 |
| --- | --- | --- |
| **轻度**（默认） | 只想更顺，不想画面变样 | 虚拟化、懒加载、生成轻量渲染、清理 will-change |
| **均衡** | 用了毛玻璃/发光主题，能接受画面变朴素 | 轻度 + 关聊天区毛玻璃/滤镜 + 停背景动画 + iframe 懒加载 |
| **极速** | 手机端、长聊天、明显掉帧 | 均衡 + 关阴影 + 关过渡 + `contain` 隔离 + 折叠历史（保留 100 条） |

单项开关也可以自由改，改完徽标会显示「自定义」，不会被预设覆盖。

## 功能

**面板位置**：`扩展` 抽屉 → 最下方 `AntiLag 流畅优化` 卡片（高级项折叠收纳，不占屏）。

- **三档模式**：轻度 / 均衡 / 极速，一键切换；HUD 里也能快捷切档。
- **体验保护**：编辑消息时暂停、选中文本时暂停、切换保持滚动位置、暂停 10 分钟做对比。
- **渲染减负**：消息虚拟化（可设阈值 30–500 条）、生成时轻量渲染、图片/iframe 懒加载、清理 will-change、关毛玻璃（可选全界面）、停动画背景、关阴影、关过渡、`contain` 隔离聊天区。
- **历史管理**：折叠较早消息（可设保留条数，默认关）；顶部「展开」随时还原，不删任何数据。
- **超长消息折叠**：单条超过阈值（默认 3000 字）先显示前段，点「展开全文」。
- **体检与归因**：实时帧率、10s 长任务次数/最长、**生成期长任务**（判断是不是流式重绘导致）、DOM 节点、毛玻璃元素、will-change 数量、动画背景、最长消息字数、已启用扩展数；并按红黄项直接给建议。
- **自动降级**：连续 3 秒低于阈值（默认 28 FPS）→ 临时升级到「极速视觉」（不折叠内容），恢复 12 秒后自动退出，不写你的设置。
- **悬浮仪表**：右下角可拖动小球，显示实时 FPS，轻点展开详情（模式、长任务、消息数 + 三档快捷切换）。

## 安装

### 方式一：手动放入（最稳）

1. 把整个 `antilag` 文件夹放到：
   - 桌面版：`SillyTavern/public/scripts/extensions/third-party/antilag`
   - 新版数据目录安装：`SillyTavern/data/<你的用户名>/extensions/antilag`
2. 重启 SillyTavern（或刷新页面）。
3. 打开「扩展」抽屉，确认出现 `AntiLag 流畅优化` 卡片并处于启用状态。

### 方式二：从本地 zip 安装

1. 解压 `antilag.zip`；
2. 按方式一把解压出的 `antilag` 目录放到位；
3. 刷新页面。

### 方式三：扩展管理器 URL 安装

在「扩展 → 安装扩展」里填仓库地址：

```
https://github.com/Neohero521/SillyTavern-AntiLag
```

（仓库根目录已带 `manifest.json`，可直接识别。）

## 建议怎么用

1. **先点「重新检测」**，看体检结论里的红黄项：哪项红，就开对应开关。
2. **长聊天（>300 条）**：确认「消息虚拟化」开启，阈值 120 左右最稳（更短的聊天完全不介入）。
3. **毛玻璃/发光主题**：切「均衡」，掉帧通常直接减半；画面变朴素是原理，不是 bug。
4. **手机端**：切「极速」，保留 80–150 条；`contain` 隔离能让键盘弹出时的重排更轻。
5. **想保观感**：留在「轻度」，只额外开「图片懒加载 + 生成轻量渲染」。
6. **怀疑优化本身影响体验**：点「暂停 10 分钟」，对比完再决定是否长期关某项。
7. 自动降级保持开启，它是兜底。

## 体检指标怎么看

| 指标 | 含义 | 判断 |
| --- | --- | --- |
| 帧率 | rAF 实测帧率 | 低于阈值（默认 28）就是真卡；45 以下算偏黏 |
| 消息条数 | 当前聊天消息数量 | 300 以上必须开虚拟化 |
| DOM 节点 | 页面元素总数 | 4000 以上渲染树偏重（长聊天 + 多扩展 UI） |
| 10s 长任务 | 最近 10 秒主线程阻塞次数 / 最长一次 | 单次 >150ms 会有可感知的「顿一下」 |
| 生成期长任务 | 本次生成期间的长任务次数 | >3 次说明流式重绘偏重，开「生成时轻量渲染」 |
| 毛玻璃元素 | 抽样 30 条消息中含 `backdrop-filter`/`filter` 的数量 | 大于 0 就值得关掉 |
| will-change | 抽样消息里非 auto 的 will-change 数量 | >2 说明主题在滥用，建议清理 |
| 动画背景 | 背景是否在动或 fixed | 是则滚动必掉帧 |
| 最长消息 | 最近 40 条里最长的字符数 | 超过 5000 字建议开「超长消息折叠」 |
| 已启用扩展 | `extension_settings` 模块数 | 超过 10 个建议逐个排查（尤其自带 `setInterval` 的） |

## 技术实现

- 只用 `SillyTavern.getContext()` 稳定 API（`eventSource` / `eventTypes` / `extensionSettings` / `saveSettingsDebounced`），不 import 内部模块。
- 所有样式注入挂在 `html.antilag` / `body.antilag` 根类上，关总开关即整段移除，不留痕。
- 虚拟化闸门单独维护：消息增长时只重算「是否够阈值」，不重建整段 CSS；阈值以下完全不介入。
- 帧率用 `requestAnimationFrame` 分秒采样；长任务用 `PerformanceObserver({entryTypes:['longtask']})`，不可用时静默降级。
- 生成期由 `GENERATION_STARTED` / `GENERATION_ENDED` / `GENERATION_STOPPED` 驱动：进入时断开 `MutationObserver`（不跟流式抢主线程），结束时重连并补一次扫描。
- 页面隐藏（切后台/锁屏）时暂停扫描，回来再补，避免后台无意义开销。
- 聊天区 `MutationObserver` 扫描做 420ms 防抖；数字输入框刷新时跳过正在编辑的输入，不会每 5 秒吃掉你的按键。
- 设置存 `extension_settings['antilag']`，随 SillyTavern 正常保存；暂停状态带时间戳，过期自动恢复。

## 边界与副作用

- **不改内容**：不动消息文本、不重写正则、不影响世界书扫描与出戏质量。
- **虚拟化的代价**：视口外消息不参与布局，极少数情况下「跳转到很早的消息」定位会有轻微偏差；在意可关该项或调高阈值。
- **关闭毛玻璃**：视觉会明显变朴素（这是它的原理）。
- **折叠历史 / 超长折叠**：只是不渲染/裁剪显示，不删除；都能一键还原，切聊天后折叠状态重置。
- **`contain: layout`**：极速档启用，会隔离聊天区与外部布局的相互影响；若你的主题依赖「聊天区撑开页面高度」，可关掉该项。
- **不支持 `longtask` 的浏览器**：体检里长任务恒为 0，其余功能正常。
